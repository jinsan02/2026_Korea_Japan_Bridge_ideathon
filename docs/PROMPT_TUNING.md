# AI Door 프롬프트·모델 설정 가이드

## 현재 적용된 구성

| 항목 | 현재값 | 판단 |
|---|---|---|
| OpenAI 기본 모델 | `gpt-5.6-luna` | 빠른 기본 분석용으로 유지 |
| OpenAI 재검증 모델 | `gpt-5.6-terra` | 안전 검증 실패 시 1회만 사용 |
| OpenAI 이미지 detail | `high` | 작은 글자가 있는 공문서이므로 유지 |
| 최대 출력 | `3000` tokens | 전체 근거 JSON이 잘리지 않도록 유지 |
| 저장 | `store: false` | 문서 이미지 보존 방지 목적, 유지 |
| 스키마 재시도 | 1회 | 무한 재시도 방지, 유지 |
| Ollama 모델 | `qwen3-vl:4b` | 8GB VRAM 시연 기본값 |
| Ollama context | `8192` | 전체 스키마와 이미지 처리를 위해 유지 |

## 이번에 줄인 부분

- OpenAI는 Structured Outputs로 전체 JSON Schema를 이미 전달한다.
- 따라서 OpenAI 요청에서는 한국 세금·일본 건강검진·한국 복지 예시 3개를 제외했다.
- 로컬 `qwen3-vl:4b`에는 출력 형태 학습을 돕기 위해 예시를 계속 전달한다.
- 안전 규칙, 원문 근거 연결, 날짜·금액·연락처 추측 금지는 제거하지 않았다.
- 프롬프트 버전은 `2026-08-27.2`로 올렸다.

## 지금 더 줄이지 말아야 할 것

- `detail: high`: 공문서의 작은 날짜, 금액, 전화번호 OCR에 필요하다.
- `max_output_tokens: 3000`: 근거와 행동 카드가 포함된 JSON은 길다.
- `store: false`: 개인정보 보호 설정이다.
- Zod 검증과 `hardenAnalysis`: 프롬프트가 실패해도 위험한 출력을 막는 코드 안전장치다.
- 사람 확인 조건과 연락처 추측 금지 규칙: 서비스의 핵심 신뢰 장치다.

## 다음 A/B 테스트 후보

한 번에 한 항목만 바꾸고 같은 합성문서 세트로 비교한다.

1. OpenAI reasoning effort 기본값과 `low` 비교
   - 측정: 응답 시간, 총 토큰, 필드 정확도, 재시도율
   - 문서 추출 정확도가 같으면 `low`를 채택한다.
2. `gpt-5.6-luna`와 `gpt-5.6-terra` 비교
   - Luna를 기본값으로 유지하되, 일본어 세로쓰기나 저화질 문서에서만 Terra가 유의미한지 확인한다.
3. 이미지 긴 변 `1600px`와 `2000px` 비교
   - 작은 글자 정확도가 늘지 않으면 1600px를 유지한다.

## 최소 평가 세트

한국어·일본어 각각 아래 문서 5개 이상, 총 10개 이상을 준비한다.

- 세금 고지서
- 건강검진 안내
- 복지 신청 안내
- 공과금 또는 가스요금 안내
- 법원·행정기관 문서

각 문서에서 다음을 채점한다.

- 문서 종류
- 발급기관
- 날짜
- 금액
- 준비물·다음 행동
- 연락처 원문 일치
- 근거 문장 일치
- 추측 발생 여부
- 사용자 확인 필요 여부
- 응답 시간과 재시도 횟수

정확도와 안전성이 유지된다는 증거 없이 프롬프트나 출력 한도를 더 줄이지 않는다.
