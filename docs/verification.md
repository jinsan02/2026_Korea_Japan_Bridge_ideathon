### 프로덕션 빌드

기존 `.next` 캐시와 함께 첫 시도는 Next.js 헤더 이후 진행되지 않았다. 캐시를 삭제하지 않고
별도 폴더로 이동한 뒤 다음 명령으로 클린 빌드했다.

npm run build

## 보안 설정 대조

- Git이 추적하는 환경 파일은 값이 비어 있는 `.env.example`뿐이다. `.env.local`은 ignore 상태다.
- 현재 파일과 전체 Git 이력에서 `sk-...` 형태의 OpenAI 비밀키 패턴은 발견되지 않았다.
- `NEXT_PUBLIC_*` API 키 변수는 없으며 서버 설정은 `server-only` 모듈에서 읽는다.
- 위 검사는 패턴 기반 점검이며 전문 secret scanner나 침투 테스트를 대체하지 않는다.
- 서버 키가 숨겨져 있어도 익명 `/api/analyze` 호출로 비용이 발생할 수 있으며,
  `ADMIN_CODE`와 인스턴스별 속도 제한은 운영 인증·분산 공격 방어가 아니다.

## 이번에 발견해 고친 것

- **시연 문서의 기한이 지나 있었다.** `tests/flow.test.ts`의 “보이는 데모 문서에 지난 기한이
  없어야 한다” 가드가 `kr-local-tax`의 납기 내 `2026-09-30`에서 실패했다. 공개 URL을 지금
  여는 방문자에게 연체 고지서가 보이는 상태였다. 데모 날짜 전체를 **1년 뒤로** 옮겼다
  (`src/lib/fixtures/` 안 62곳). 연도만 바뀌므로 “9월 30일”, “9月18日” 같은 한국어·일본어
  본문과 납기 내/후 관계는 그대로 유지된다.
- **테스트 2개가 그 날짜를 문자열로 박아 두고 있었다.** 의도는 “연습본이 실제 문서의 값을
  재사용하지 않는다”인데 날짜 리터럴 때문에 날짜를 옮길 때마다 무관해 보이는 실패가 났다.
  이제 fixture의 `importantDates`에서 기한을 읽어 비교하므로 다음에 날짜를 옮겨도 깨지지 않는다.
- **README의 업로드 상한이 실제 코드와 달랐다.** 표에 `6MB`로 적혀 있었으나 실제
  `MAX_UPLOAD_BYTES` 기본값은 `3_000_000`이다(서버리스 본문 상한 때문에 낮춘 값).
  `3MB`로 정정했다.
